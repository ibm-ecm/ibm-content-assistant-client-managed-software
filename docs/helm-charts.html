Available Charts

IBM Content Assistant Operator

v1.0.4 Namespace-scoped Latest
⬇️ Download Chart

The single Helm chart for IBM Content Assistant. Installing this operator is the only deployment step required — it automatically provisions, configures, and upgrades the GenAI Connector Service. Requires an existing IBM Content Cortex or CP4BA deployment (CPE + Content Navigator). Usage is reported to IBM via the Usage Metering Service (UMS).

Chart Version:1.0.4
App Version:1.0.4
Architecture:amd64
Operator Image:icr.io/cpopen/ibm-content-assistant-operator:1.0.4
Managed Service Image:cp.icr.io/cp/cas/genaiconnector:1.0.4

What this chart installs

  • IBM Content Assistant Operator — namespace-scoped Kubernetes operator that manages the full deployment lifecycle
  • GenAI Connector Service (deployed by the operator) — RAG-powered AI service for natural language Q&A, summarization, and document comparison
  • CRD-based configuration via a ContentAssistant Custom Resource for declarative deployment management
  • Integrates with CPE + Content Navigator on CP4BA or Content Cortex
  • Usage metering via IBM Usage Metering Service (UMS) — no manual reporting required
  • Supports watsonx.ai SaaS (IBM Cloud or AWS) and self-managed LLM endpoints
  • Supports IBM AI Model Gateway as an LLM proxy endpoint
  • Air-gap / offline deployment support

Common Configuration Values

Complete Installation Guide

Choose your preferred installation method below

1

Prerequisites

  • Kubernetes 1.24+ or OpenShift 4.12+
  • Python 3.12+
  • IBM Entitlement Key from IBM Container Library
  • Cluster admin access
2

Clone Repository and Setup Environment

git clone https://github.com/ibm-ecm/ibm-content-assistant-client-managed-software.git
cd ibm-content-assistant-client-managed-software/scripts

# Create and activate virtual environment
python -m venv venv
source venv/bin/activate  # On Windows: venv\Scripts\activate

# Install dependencies
pip install -r requirements.txt
3

Deploy Operators

# Interactive deployment with guided configuration
python deploy_operator.py

# Follow prompts to:
# - Select operators to deploy
# - Configure namespaces
# - Set image pull secrets
# - Verify prerequisites
🔒 Dev mode — GITHUB_TOKEN required. Running with --dev pulls pre-release chart artifacts from the internal GHE repository. Export your GHE personal access token (repo scope) before running the command below.

Generate a personal access token → 
export GITHUB_TOKEN=<your-ghe-token>
python deploy_operator.py --dev
4

Configure and Deploy Content

# Gather deployment properties
python prerequisites.py gather

# Generate deployment artifacts
python prerequisites.py generate

# Validate configuration
python prerequisites.py validate
1

Add Helm Repository in OpenShift

Option A: Using OpenShift Console

  • Navigate to: Developer → Helm → Repositories
  • Click Create
  • Name: ibm-content-assistant
  • URL: https://ibm-ecm.github.io/ibm-content-assistant-client-managed-software/charts

Option B: Using HelmChartRepository Resource

Create a HelmChartRepository custom resource (documentation):

apiVersion: helm.openshift.io/v1beta1
kind: HelmChartRepository
metadata:
  name: ibm-content-assistant
spec:
  name: IBM Content Assistant Charts
  connectionConfig:
    url: https://ibm-ecm.github.io/ibm-content-assistant-client-managed-software/charts
oc apply -f helmchartrepository.yaml
🔒 IBM GHE credentials required. The Pages URL is SSO-gated. OpenShift must pull chart archives from raw.github.ibm.com using basic auth credentials. See Step 2 below to create the credentials secret first, then apply this config in the same namespace: 
apiVersion: helm.openshift.io/v1beta1
kind: ProjectHelmChartRepository
metadata:
  name: ibm-content-assistant
  namespace: ibm-content
spec:
  name: IBM Content Assistant Charts
  connectionConfig:
    url: https://raw.github.ibm.com/dba/cert-kubernetes-content-assistant/gh-pages/docs
    basicAuthConfig:
      name: ibm-content-assistant-helm-credentials
oc apply -f projecthelmchartrepository.yaml -n ibm-content
2

Create GHE Credentials Secret

Generate a personal access token with repo scope at github.ibm.com → Settings → Developer settings → Personal access tokens.

Create the secret in the same namespace as the ProjectHelmChartRepository (ibm-content). The secret must have keys username and password:

oc create secret generic ibm-content-assistant-helm-credentials \
  --from-literal=username=<your-ghe-username> \
  --from-literal=password=<your-ghe-token> \
  -n ibm-content
3

  --docker-username=cp \
  --docker-password=<your-entitlement-key> \
  -n ibm-content
